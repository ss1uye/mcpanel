# MC Panel v0.2 打磨与加固设计

> 日期：2026-10-24 · 状态：待用户审阅 · 前置版本：v0.1（阶段 1–3 完成）
> 关联：`docs/superpowers/specs/2026-10-23-minecraft-server-panel-design.md`（总规格）、仓库根 `HANDOFF.md`

## 1. 背景与目标

v0.1 已具备纳管、控制台、玩家、文件、配置、备份/恢复、计划、审计与部署能力，独立代码审查通过。`HANDOFF.md` 第 9 节列出 10 项「已知限制」，其中 5 项属于体验或纵深防御缺口。

v0.2 的目标是在**不改变备份/恢复语义、不做数据库结构变更**的前提下，清掉这批限制：

1. CSP 仍允许任意 `ws:`/`wss:` 与内联样式。
2. 面板自身数据库（`data/panel.db`）只能手工备份。
3. 下载失败/创建中的备份记录会返回 404/500。
4. 文件与配置编辑器是无高亮的 `<textarea>`。
5. 计划表单不预览未来运行时间。
6. 前端单 chunk 约 800 kB，实例路由未做懒加载。

发布版本：**v0.2.0**。

## 2. 范围

### 2.1 包含

| # | 能力 | 用户可见结果 |
| --- | --- | --- |
| 1 | CSP nonce 与 connect-src 收紧 | 响应头不再含 `'unsafe-inline'`，WebSocket 仅允许当前 Host |
| 2 | 面板库在线快照 | 设置页一键下载一致性 `panel.db` 快照；附 CLI 脚本供 cron |
| 3 | 备份下载校验 | 非 `ready` 记录返回 409，文件缺失返回 404，下载文件名为真实备份名 |
| 4 | 计划未来 3 次预览 | 列表展示未来 3 次运行；表单编辑时实时预览 |
| 5 | CodeMirror 6 编辑器 | 文件编辑与配置原始编辑支持行号、搜索、JSON/YAML/properties 高亮 |
| 6 | 路由懒加载与分包 | 首屏主链不再包含 recharts；页面按路由按需加载 |

### 2.2 不包含

- 备份 manifest 与数据库存证做哈希比对（保留为已知限制）。
- 面板库自动定时快照与保留策略（本期只提供手动下载与 CLI）。
- 远程节点、多用户、外部存储、告警（仍属总规格 §24 路线）。
- 任何数据库 schema 变更或迁移。

## 3. 架构与组件

### 3.1 CSP：按请求 nonce + Host 限定

现状：`apps/server/src/app.ts` 中 `SECURITY_HEADERS` 是静态常量，`style-src` 含 `'unsafe-inline'`，`connect-src` 为 `'self' ws: wss:`。

设计：

- `onRequest` 钩子为每个请求生成 nonce：`randomBytes(16).toString('base64')`，存放在请求装饰属性上；`onSend` 动态组装 CSP。
- 新的 CSP 指令：
  - `default-src 'self'`
  - `script-src 'self'`
  - `style-src 'self' 'nonce-<nonce>'`
  - `img-src 'self' data:`
  - `font-src 'self'`
  - `connect-src 'self' ws://<host> wss://<host>`（Host 合法时），否则仅 `'self'`
  - `frame-ancestors 'none'`、`base-uri 'none'`、`form-action 'none'`
- Host 校验正则：`/^(?:[A-Za-z0-9.-]+|\[[0-9A-Fa-f:.]+\])(?::\d{1,5})?$/`；来自 `request.headers.host`，缺失或非法时不追加 ws 源。
- `apps/web/index.html` 增加 `<meta name="csp-nonce" content="__CSP_NONCE__" />`。
- 服务端启动时预读构建后的 `index.html` 模板，提供 `renderIndex(nonce)`：
  - 替换 `__CSP_NONCE__`；
  - 模板无占位符时在 `</head>` 前注入 meta（无 head 则前置）；
  - 响应头 `Cache-Control: no-store`。
- 静态托管：`@fastify/static` 设置 `index: false`；新增 `GET /` 与 `GET /index.html` 路由返回 `renderIndex`；SPA fallback 同样返回 `renderIndex`。
- 关闭 Vite 的 `build.modulePreload.polyfill`，避免内联 script 触发 `script-src 'self'`；现代 Chromium/Firefox/Safari 均原生支持 modulepreload。
- CodeMirror 通过 `EditorView.cspNonce.of(nonce)` 让动态 `<style>` 携带 nonce；nonce 从 meta 读取。
- React 的内联 `style` 属性（如 `PlayerAvatar`）经 CSSOM 设置，不受 `style-src` 限制。

### 3.2 面板库在线快照

新增 `apps/server/src/services/panel-backup-service.ts`：

```ts
interface PanelBackupServiceDeps {
  sqlite: Database.Database;   // better-sqlite3 句柄
  dataDir: string;
}
class PanelBackupService {
  createSnapshot(): Promise<{ path: string; filename: string; sizeBytes: number }>;
}
```

- 文件名 `panel-YYYYMMDD-HHmmss.db`（UTC，复用备份时间戳风格）；同一秒冲突时追加 4 位随机十六进制。
- 目标目录 `data/tmp/`，使用 better-sqlite3 的 `db.backup(path)` 在线备份 API（WAL 下保持一致）。
- 快照生成后 `stat` 取大小并返回；不包含 `.env`、`secret.key`。
- `AppServices` 增加可选的 `panelBackup`；`index.ts` 以 `handle.sqlite` 与 `config.dataDir` 构造并注入，路由仅在存在该服务时注册（保持现有测试可独立组装）。

路由（`apps/server/src/routes/settings.ts`）：

- `GET /api/settings/panel-backup`：`requireAuth`，无 CSRF（GET，仅认证）。
- 响应：`Content-Type: application/vnd.sqlite3`、`Content-Disposition: attachment; filename="panel-….db"`。
- 审计：`panel.backup`，`targetType: 'panel'`，`targetId: null`，`detail: { filename, sizeBytes }`。
- 清理：读流 `close`/`error` 时删除临时文件；流正常结束自动触发 `close`。快照生成失败记录日志并返回 500。

CLI：`scripts/backup-panel-db.mjs [输出路径]`

- 读取仓库根 `.env`（存在时），`DATA_DIR` 默认 `./data`；
- 默认输出 `data/backups-panel/panel-<时间戳>.db`，自动建目录；
- 使用 `better-sqlite3` 打开 `data/panel.db` 并 `backup()`，打印输出绝对路径；
- 面板运行中可执行。

### 3.3 备份下载校验

`BackupService` 新增：

```ts
downloadable(instanceId: string, backupId: string): { path: string; filename: string };
```

- 记录不存在 → `AppError('NOT_FOUND')`（404）。
- 状态非 `ready` → `AppError('INVALID_STATE', '备份尚不可下载')`（409）。
- 文件 `stat` 失败 → `NOT_FOUND`（404）。
- 路由使用返回的真实文件名，替换当前硬编码的 `backup.zip`；审计仍在校验通过后记录。
- 前端 `BackupList` 已经按 `status === 'ready'` 禁用下载，不改交互。

### 3.4 计划未来 3 次运行

- 共享类型 `ScheduleInfo` 增加 `nextRuns: string[]`（ISO UTC，最多 3 条）。
- `ScheduleService` 提取纯函数 `nextRunsFor(cron, timezone, count = 3)`：croner 以 `paused: true` 创建、`nextRuns(3)`、`finally stop()`；异常返回 `[]`。
- `toInfo` 统一附加 `nextRuns`；列表、创建、更新返回均带该字段。
- 新预览接口：`GET /api/instances/:id/schedules/preview?cron=<cron>&timezone=<tz>`：
  - 校验实例存在；
  - 查询参数用共享 zod schema 校验（cron 1–100 字符、timezone 1–64 字符）；
  - 返回 `{ nextRuns: string[] }`；
  - 非法 cron/时区 → 400 `INVALID_CRON`。
- 该路由为静态路径，Fastify 优先级高于 `/:scheduleId`，但仍声明在参数路由之前以保持可读性。

前端：

- `SchedulesTab` 在启用计划的下次时间后追加「未来：A · B · C」，停用计划不展示。
- `ScheduleForm` 对 cron/时区做 300ms 防抖预览；请求失败显示「cron 表达式或时区无效」但**不禁用保存**，最终由后端校验。

### 3.5 CodeMirror 6 编辑器

新增依赖（`apps/web`）：`codemirror`、`@codemirror/state`、`@codemirror/view`、`@codemirror/language`、`@codemirror/lang-json`、`@codemirror/lang-yaml`、`@codemirror/legacy-modes`、`@codemirror/theme-one-dark`。

新增组件：

- `apps/web/src/components/CodeEditor.tsx`（默认导出，供 `React.lazy`）：
  - props：`value`、`onChange`、`ariaLabel`、`heightClass`（默认 `h-80`）。
  - `basicSetup` + `oneDark` + 主题覆盖：背景 `var(--console-bg)`、前景 `var(--console-fg)`、等宽字体。
  - `EditorView.lineWrapping`、2 空格缩进、`EditorView.contentAttributes` 写入 `aria-label`。
  - `EditorView.cspNonce.of(readCspNonce())`。
  - 受控同步：`value` 变化且与当前文档不同时 dispatch 替换，保持光标尽量稳定；卸载时 `view.destroy()`。
  - `height: 100%`，外层容器固定高度、`overflow: auto`。
- `apps/web/src/utils/editor-language.ts`：
  - 按扩展名选择 `json` / `yaml` / `properties`（`StreamLanguage.define(properties)`）/ 纯文本；
  - 大小写不敏感；无扩展名或未知返回 `null`。

接入：

- `FileEditorDialog`：替换 textarea；冲突重载时 `setContent` 触发文档同步；加载中/失败逻辑不变。
- `ConfigTab` 原始编辑：替换 textarea，保留 aria-label `server.properties 内容`，`heightClass="h-96"`。
- 两处用 `<Suspense fallback={<Spinner />}>` 包裹，编辑器 chunk 仅在打开时加载。

### 3.6 路由懒加载与分包

- `apps/web/src/router.tsx`：所有页面组件改为 `React.lazy(() => import(...))`；为每个页面文件补充 `export default`（保留现有命名导出，测试不受影响）。
- 顶层 `<Suspense fallback={<Spinner />}>` 包住 `<Routes>`；`AppShell`、`InstanceLayout` 保持静态导入，避免外壳闪烁。
- `apps/web/vite.config.ts`：
  - `build.modulePreload.polyfill = false`；
  - `build.rollupOptions.output.manualChunks`：`react`（react、react-dom、react-router-dom）、`charts`（recharts）；CodeMirror 由其动态导入自动独立成 chunk。
- 交付时记录 `vite build` 前后入口主链体积。

## 5. 错误处理

- 面板快照：备份 API 抛错（磁盘满、IO）→ 记录 `err` 日志并返回 500 `INTERNAL`；临时文件失败时尽力删除。
- 并发快照：文件名唯一，互不覆盖；各自清理。
- 下载：校验失败不创建读流，不写审计；校验通过后写 `backup.download`。
- preview：cron 或时区非法统一 400 `INVALID_CRON`；实例不存在 404。
- CodeMirror chunk 加载失败：Suspense fallback 停留 Spinner；不阻塞页面其他功能（刷新可恢复）。
- 模板缺少 nonce 占位符：自动注入 meta；e2e 验证 nonce 与响应头一致。

## 6. 安全考量

- nonce 只出现在响应头与 meta，不写日志、不入 URL；每次请求重新生成。
- `connect-src` 只放行当前 Host 的 ws/wss，杜绝任意 WS 目标；Host 非法时退回 `'self'`。
- 面板快照包含密码哈希、会话哈希、审计与设置；下载仅限已认证管理员，并记审计。恢复快照需停服，文档提示同时保存 `.env`/`secret.key`（后者不入快照）。
- 下载文件名取自数据库内受控值（时间戳 + UUID 前缀），不使用用户输入。
- 不改变路径沙箱、备份冻结与恢复回滚的既有安全语义。

## 7. 测试计划

### 7.1 服务端（Vitest）

- `backups-api`：失败记录下载 → 409；删除文件后的 ready 记录 → 404；正常下载 → 200 且 `Content-Disposition` 含真实文件名。
- `settings-api` 或新文件：
  - 快照响应以 `SQLite format 3\0` 开头；
  - 用 better-sqlite3 打开快照可读到 `users`/`settings` 表；
  - 审计出现 `panel.backup`；
  - 响应后 `data/tmp` 中无残留文件。
- `schedules-api`：列表 `nextRuns` 长度 3 且为合法 UTC；preview 正常；非法 cron/时区 → 400 `INVALID_CRON`。
- `spa`/安全：CSP 头不含 `unsafe-inline`；HTML meta 中 nonce 与响应头一致；`connect-src` 含请求 Host；非法 Host 回退 `'self'`；`/` 返回 `no-store`。
- `schedule-service`：`nextRunsFor` 时区换算与异常返回空数组。

## 9. 风险与回退

| 风险 | 缓解 |
| --- | --- |
| CodeMirror 样式被 CSP 拦截 | `EditorView.cspNonce` + e2e 断言无违规；若该版本不支持 nonce，回退为全局保留 `style-src 'unsafe-inline'`、仅收紧 `connect-src`，并在 HANDOFF 记录 |
| Vite 内联脚本触发 CSP | 关闭 modulePreload polyfill；e2e 控制台检查 |
| 快照 API 在 WAL 下不一致 | 使用 better-sqlite3 官方 `backup()`；测试打开快照读表 |
| 新增依赖体积 | 编辑器独立异步 chunk；记录首屏体积前后值 |
| 懒加载导致首屏白屏 | 顶层 Suspense；保留外壳静态加载；e2e 覆盖 |
